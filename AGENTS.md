# AGENTS.md — правила для ИИ-агентов (Claude Code, Codex и др.)

Этот файл — единственный источник правил для агентов. `CLAUDE.md` его импортирует.
Обзор игры и архитектуры: [README.md](README.md). Процесс команды: [CONTRIBUTING.md](CONTRIBUTING.md).

## Команды

```bash
pip install -r requirements-dev.txt   # зависимости разработки (рантайм — requirements.txt)
pytest -q                             # все тесты, временная БД, без сети
ruff check --fix .                    # линтер
ruff format .                         # форматирование
docker compose build                  # сборка образа
```

Готово = `ruff check .`, `ruff format --check .` и `pytest -q` проходят без ошибок.

## Слои (не смешивать)

- `app/bot/` — только Telegram: разбор команд, клавиатуры, форматирование. Без SQL и игровых расчётов.
- `app/services/` — игровые правила. Не импортирует aiogram. Возвращает dataclass-результаты из `app/models.py`, ошибки бросает как `GameError` и наследников из `app/errors.py`. Текст ошибки показывается игроку, поэтому пишется по-русски.
- `app/db/` — подключения, миграции и запросы (`repositories.py`).
- `app/constants.py` — весь контент и баланс: цены, корабли, рецепты, квесты. Числа не дублировать в других местах.

## Инварианты (нарушение — баг, даже если тесты зелёные)

1. Деньги, количества и цены — только `int`. Никаких `float` в расчётах; проценты считаются через `* pct // 100`.
2. Любая мутация выполняется внутри `async with self.ctx.db.transaction() as conn:` (`BEGIN IMMEDIATE`). Внутри одной транзакции: прочитать состояние, проверить, изменить.
3. Баланс меняется только через `repo.change_balance` (не даёт уйти в минус), доход — через `progression.earn`. Товар меняется только через `repo.add_item` и `repo.remove_item`. Перед списанием проверяется доступное количество с учётом P2P-резерва (`repo.get_reserved` / `repo.available_quantity`).
4. Ни одного вызова Telegram API внутри транзакции. Сообщения отправляются после выхода из сервиса.
5. Кнопка, которая меняет состояние, выдаётся через `TokenService.issue`. Сервис гасит токен через `repo.consume_token` в той же транзакции, что и действие (см. `app/bot/handlers/actions.py`). Read-only навигация идёт через `NavCB`.
6. Переходы статусов P2P-предложений и PvP-вызовов делаются только через `UPDATE … WHERE status = 'pending'` с проверкой `rowcount`. Возврат ставки — через `_close_with_refund` в `app/services/pvp.py`.
7. Время берётся только из `self.ctx.clock.now()`, случайность — только из `self.ctx.rng`. Не использовать `time.time()`, `datetime.now()` и модуль `random` в сервисах.
8. XP, прогресс квестов и достижения начисляются в транзакции действия через `app/services/progression.py`, причём только при успехе.
9. SQL только с параметрами `?`. Имена столбцов в f-строках допустимы только из белых списков в коде.
10. Пользовательские строки в HTML-ответах экранируются через `esc()` / `mention()` из `app/bot/formatting.py`.

## Миграции

- Миграцию `V1` в `app/db/migrations.py` **не редактировать**: на проде она уже применена.
- Изменение схемы — это новый элемент `MIGRATIONS` со следующим номером и списком SQL-выражений. При необходимости добавляется seed в `SEEDS`.
- Если после rebase номер уже занят чужой миграцией, свою нужно перенумеровать. Тест `test_migration_versions_are_contiguous` проверяет нумерацию.

## Тесты

- Новое правило или исправление — вместе с тестом в `tests/`.
- Фикстуры и хелперы лежат в `tests/conftest.py`: `game`, `clock` (`FixedClock`), `rng` (`ScriptedRandom`: значения задаются через `rng.ints` и `rng.picks`), `make_user`, `give_items`, `set_ship`, `snapshot`. `snapshot` подходит для проверки, что неуспешная операция ничего не изменила.
- Сценарии через Telegram проверяются через `Harness` в `tests/test_handlers.py`: настоящий `Dispatcher` и записывающий `Bot`.
- Тесты, которые не проходят, нельзя удалять, пропускать или ослаблять, чтобы CI стал зелёным.

## Git и PR

- Одна задача — одна ветка: `feat/…`, `fix/…`, `chore/…`, `docs/…`. **Не коммитить и не пушить в `main`**, не делать force-push в чужие ветки, не мержить PR. Мержит человек.
- Сообщения коммитов в формате Conventional Commits (`feat: …`, `fix: …`). Коммиты маленькие и логически цельные. Форматирование не смешивать с логикой.
- PR оформляется по шаблону `.github/pull_request_template.md`. В нём указывается, что изменения сделаны с помощью ИИ.
- Если в одном клоне параллельно работают несколько агентов, каждый работает в своём `git worktree`.

## Запрещено

- Читать, выводить или менять `.env` и файлы в `data/` и `backups/`: там токен бота, `GAME_SEED` и боевая база.
- Менять `GAME_SEED` и формулы цен в `app/services/economy.py` без явного запроса: это сдвигает цены у всех игроков.
- Запускать `deploy.sh`, `ssh`, `scp` и любые команды на сервере. Деплоит только человек.
- Добавлять зависимости без явной просьбы. Если зависимость нужна, версия закрепляется в `requirements*.txt`.
- Коммитить секреты, БД, архивы и `.venv`.

## Стиль

Python 3.11+, аннотации типов, `from __future__ import annotations`, длина строки 120 (ruff). Тексты для игроков — по-русски, с эмодзи, как в существующих сообщениях. Комментарии и docstring — по-русски.
