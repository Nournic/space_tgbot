# 🚀 Космический Трейдер 1.0

Многопользовательская текстовая космическая RPG-экономика для Telegram-групп и супергрупп.
Торговля между 6 планетами, динамические цены, добыча, производство, корабли и модули,
PvE-охота на пиратов, добровольные PvP-дуэли со ставками, P2P-сделки, задания, достижения,
рейтинги, кланы и мировые события.

Стек: Python 3.11+, aiogram 3.x (long polling), SQLite + aiosqlite, pytest.

> Игровые кредиты — вымышленная, невозвратная и неконвертируемая валюта. Никаких платежей, криптовалюты и призов.

## Установка и запуск

1. Установите Python 3.11 или новее (`python --version`).
2. Создайте виртуальное окружение и поставьте зависимости:

   ```bash
   python -m venv .venv
   # Windows: .venv\Scripts\activate     Linux/macOS: source .venv/bin/activate
   pip install -r requirements.txt        # только для запуска бота
   pip install -r requirements-dev.txt    # для разработки: + pytest, ruff
   ```

3. Создайте бота у [@BotFather](https://t.me/BotFather): `/newbot` → получите токен.
4. Скопируйте `.env.example` в `.env` и впишите токен:

   ```env
   BOT_TOKEN=123456:ABC...
   DATABASE_PATH=data/space_trader.sqlite3
   GAME_SEED=space-trader-1.0
   ```

5. Запустите:

   ```bash
   python main.py
   ```

При первом старте создаются папка `data/` и база с полной схемой (миграция v1).
Повторный запуск безопасен: применённые миграции пропускаются. При старте бот сразу
закрывает истёкшие за время простоя вызовы/предложения (ставки возвращаются) и
регистрирует список команд через `set_my_commands`.

### Запуск в Docker

```bash
cp .env.example .env        # впишите BOT_TOKEN
docker compose up -d --build
docker compose logs -f bot
```

База хранится в именованном томе `space_trader_data` (`/app/data` в контейнере) и переживает
пересборку и перезапуск. `DATABASE_PATH` в контейнере зафиксирован compose-файлом. Контейнер
работает от непривилегированного пользователя `bot` (uid 1000), перезапускается автоматически
(`restart: unless-stopped`), логи ротируются (3 × 10 МБ).

Резервная копия из работающего контейнера:

```bash
docker compose exec bot python backup.py data/backups/st.sqlite3
docker compose cp bot:/app/data/backups/st.sqlite3 ./st.sqlite3
```

### Деплой на VPS

На сервере нужны Docker с плагином compose и SSH-доступ (в примерах хост `vps_server` из
`~/.ssh/config`). Один раз положите `.env` на сервер:

```bash
ssh vps_server "mkdir -p ~/space_tgbot" && scp .env vps_server:~/space_tgbot/.env
```

Деплой текущего коммита (`HEAD`; незакоммиченные изменения не попадут в архив):

```bash
git archive --format=tar.gz -o bot.tgz HEAD && scp bot.tgz vps_server:~/bot.tgz && ssh vps_server "mkdir -p ~/space_tgbot && tar -xzf ~/bot.tgz -C ~/space_tgbot && rm ~/bot.tgz && cd ~/space_tgbot && docker compose up -d --build" && rm bot.tgz
```

То же самое скриптом: `./deploy.sh [хост] [папка]` (по умолчанию `vps_server` и `space_tgbot`).
Архив не содержит `.env` и данных, поэтому распаковка их не затрагивает. Файлы, удалённые из
репозитория, на сервере останутся — они не мешают, но при желании их можно удалить вручную.

### Работа в группах

* Добавьте бота в группу. **Privacy mode отключать не нужно**: бот реагирует только на команды.
* `/challenge`, `/offer` и `/clan transfer` отправляются **ответом** на сообщение другого игрока —
  Telegram передаёт боту команду вместе с `reply_to_message`.
* Один Telegram-аккаунт = один игровой аккаунт во всех чатах. Кнопки чужих игроков не работают
  («⛔ Эта кнопка не для вас»).

## Правила и формулы

**Старт:** 1 000 кр., Земля, уровень 1, «Шаттл» (трюм 20, HP 100), энергия 100.

**Уровень:** `level = 1 + total_xp // 100`. XP: сделка на рынке +1, перелёт +2, добыча +3,
крафт +2 (за операцию), PvE победа 15/20/30, поражение 5; PvP победа 20, поражение 5, ничья 3.

**Карта** (двусторонние маршруты, стоимость в энергии): Земля–Марс 10, Земля–Венера 8,
Марс–Церера 12, Марс–Европа 18, Венера–Церера 16, Церера–Европа 12, Европа–Титан 22.
Цена перелёта = ребро − уровень двигателя, минимум 5. Кулдаун 60 с.

**Цены:** база из конфига × (100 + ежедневное отклонение −20..+20% + событие ±10%) / 100,
ограничение 70–130% базы, округление вниз, минимум 1. Отклонение и событие вычисляются
SHA-256 от `(seed, UTC-дата, планета, товар)` — одинаково для всех, не меняется при рестарте,
не зависит от часового пояса. Продажа = `max(1, floor(покупка × 0.9))`.
Цена всегда пересчитывается на сервере внутри транзакции.

**Энергия:** максимум 100, +1 за каждые 5 полных минут. Регенерация ленивая по сохранённому
якорю; неполный интервал не теряется; на максимуме якорь переносится на «сейчас», поэтому
время простоя на максимуме не превращается в скрытый запас.

**Корабли:** Шаттл (старт, 20/100), Разведчик 2 500 (30/110, ур. 3, атака +2),
Грузовик 6 000 (65/140, ур. 6), Корвет 10 000 (45/190, ур. 10, атака +6).
Покупка заменяет корпус, сохраняя модули, груз и энергию; прочность — полный максимум нового
корпуса. Нельзя купить текущий класс и нельзя, если груз не помещается.

**Модули** 0–5, переход на уровень n стоит 500 × n: трюм +10/ур., двигатель −1 энергии/ур.,
оружие +4 к силе/ур., броня +25 макс. HP и −2 входящего урона/ур. (урон ≥ 1).
Улучшение брони не лечит корабль. **Ремонт:** 5 кр. за 1 HP. При HP 0 нельзя летать, добывать и воевать.

**Добыча:** 12 энергии, кулдаун 30 с, 1–4 единицы разрешённого на планете ресурса.
Если добыча не помещается — отказ до списания энергии и кулдауна.

**Крафт:** fuel_cell = 2 water + 1 silicon; electronics = 2 iron + 2 silicon;
medicine = 2 water + 1 spice. Работа 10 кр. × количество. Зарезервированные P2P товары не используются.

**PvE:** 15 энергии, кулдаун 30 с. Сила игрока = `10 + 4×оружие + бонус класса + d20`.
**Ничья в пользу игрока** (сила ≥ силы пирата — победа). Победа: награда и урон 5–12;
поражение: +5 XP, урон 20–40 (оба снижаются бронёй). Груз не теряется. На дальних планетах
чаще встречаются сильные пираты (веса в `app/constants.py`).

**PvP:** вызов живёт 5 минут; ставка инициатора сразу уходит в escrow (строку вызова).
При принятии проверяются планета, энергия (10 у каждого), HP и деньги адресата.
Сила дуэли = атака по PvE-формуле + 2 × броня; большая побеждает, равная — ничья.
Проигравший получает 20–35 урона, победитель (и оба при ничьей) — 0–10, всё снижается бронёй.
Победитель забирает обе ставки, при ничьей ставки возвращаются. Отклонение, отмена и
истечение возвращают ставку ровно один раз. XP за дуэли одной пары — не чаще раза в час.

**P2P:** `/offer water 5 200` — продать 5 воды за 200 кр. суммарно (0 — подарок), 5 минут.
Товар остаётся в трюме продавца, но резервируется: `available = total − активные резервы`.
При принятии деньги и товар переходят атомарно; P2P не создаёт и не уничтожает кредиты.

**Задания (UTC):** daily_sell (10 ед. на рынок, 150 кр./15 XP), daily_travel (2 перелёта,
100/10), daily_mine (5 ед., 120/12), daily_pirate (1 победа, 200/20). Создаются лениво,
прогресс ограничен целью, награда — ровно один раз и только за текущий день.

**Достижения** (без денежных наград): первая сделка, 100 сделок, 10 перелётов, 100 добытых,
10 побед PvE, 10 побед PvP, 10 000 кр. на балансе, 25 производств.

**Кланы:** создание 1 000 кр., до 30 участников, название 3–32 символа (буквы, цифры, пробел,
`.-_`), уникально без учёта регистра. Лидер выходит только после `/clan transfer` или
`/clan disband` (одноразовое подтверждение). **Казна при роспуске сгорает.**

**События дня:** quiet, water_shortage (+10% вода), industrial_boom (+10% железо и кремний),
spice_glut (−10% спайс), tech_rush (+10% электроника).

## Архитектура

```text
main.py            запуск, логирование (токен маскируется), фоновая очистка, polling
config.py          настройки из .env
backup.py          онлайн-резервная копия SQLite
Dockerfile, docker-compose.yml, deploy.sh   контейнер и деплой на VPS
app/constants.py   весь игровой контент и баланс
app/models.py      dataclass-DTO и результаты операций
app/errors.py      игровые исключения с текстом для игрока
app/clock.py       источник времени (подменяется в тестах), UTC-даты
app/db/            connection (соединение на операцию, WAL, BEGIN IMMEDIATE),
                   migrations (PRAGMA user_version + schema_migrations), repositories (SQL)
app/services/      бизнес-правила без Telegram: accounts, economy, events, travel, ships,
                   mining, crafting, combat, pvp, offers, quests, progression, clans, rankings
app/bot/           handlers (только разбор апдейтов и ответы), keyboards (CallbackData),
                   formatting (HTML + экранирование), middlewares, routers
app/tasks.py       единственная фоновая задача очистки
tests/             pytest-тесты (сервисы, хендлеры, конкурентность)
```

**Транзакционная модель.** Каждая операция открывает своё соединение. Все изменения денег,
инвентаря, HP, энергии, ставок, наград и кланов выполняются в `BEGIN IMMEDIATE`: состояние
читается, проверяется и изменяется в одной транзакции, при исключении — `ROLLBACK`.
`PRAGMA foreign_keys=ON` и `busy_timeout` ставятся для каждого соединения. Вызовы Telegram
выполняются только после commit, поэтому ошибка Telegram не отменяет совершённую операцию.

**Одноразовые кнопки.** Мутирующие кнопки содержат короткий токен из таблицы `action_tokens`
(владелец, чат, действие, payload, срок). Сервис погашает токен **в той же транзакции**, что
и действие: повторное нажатие/старая клавиатура → «⏳ Действие устарело»; если действие не
удалось (например, не хватило денег), токен остаётся активным. Payload привязывает кнопку к
планете/товару/дате. P2P и дуэли защищены статусной машиной (`UPDATE … WHERE status='pending'`).

**Членство в кланах** хранится только в `clan_members` (у `users` нет `clan_id`).

**Журнал `ledger`** фиксирует каждую финансовую и товарную операцию с балансом после неё;
источник истины для баланса — `users.balance`.

## Тесты

```bash

```

Тесты используют временную БД (`tmp_path`), управляемые часы `FixedClock` и сценарный RNG.
Покрыто: регистрация и миграции, ограничения схемы, рынок и стабильность цен, смена суток,
вес груза, резервы и конкурентное принятие P2P, перелёты, энергия, корабли, ремонт, добыча и

кланы (лимит 30 при гонке), одноразовые токены, сквозные тесты хендлеров через настоящий
`Dispatcher` с подменённым `Bot`, перезапуск сервисов.

## Резервное копирование

```bash
python backup.py                    # backups/space_trader-YYYYmmdd-HHMMSS.sqlite3
python backup.py D:/backups/st.sqlite3
```

Используется `sqlite3.Connection.backup` — консистентная копия даже при работающем боте
(в режиме WAL), затем `PRAGMA integrity_check`. Восстановление: остановите бота, замените
файл `data/space_trader.sqlite3` копией, удалите рядом лежащие `-wal`/`-shm`, запустите бота.
Файлы БД, WAL/SHM, `backups/` и `.env` исключены из Git.

## Устранение проблем

* **`BOT_TOKEN не задан`** — создайте `.env` из `.env.example`.
* **`TelegramConflictError`** — бот запущен где-то ещё (или с webhook). Остановите другой экземпляр.
* **`database is locked`** — БД открыта внешней программой с долгой транзакцией; закройте её.
* **Бот молчит в группе** — проверьте, что команда адресована боту (`/market@имя_бота` при
  нескольких ботах) и бот является участником группы.
* **Кнопка «устарело»** — откройте меню командой заново: одноразовые клавиатуры живут 15 минут.
